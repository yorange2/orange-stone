## 为什么做

引擎当前覆盖经典（316）+ 现代核心系列（270 张真实卡）。2025–2026 扩展是下一步：

1. **真实的炉石现在**。任何 SabberStone 对拍对比、任何"当前标准环境"的训练主张，
   都需要真实的标准系列卡池，而不是 2021 年代的卡池。2025–2026 才是现役环境。
2. **机制深度**。这五个系列引入了引擎从未有过的机制：英雄技能强化（灌注）、
   任务区（安戈洛）、效果重放（时光倒流）、附属部件随从（巨像）、卡牌分裂（粉碎）、
   规则覆写（破规者）。每一个都是常驻引擎原语，不是打补丁——与核心系列 W 波的
   收益形态一致。
3. **顺带还债**。翡翠梦境的"全职业 Choose One"会正面撞上已登记的
   Choose-One-自动随机简化——本路线图是正式清偿它的自然时机。

**本文件是架构与索引。** 卡级清单在各子路线图里，由数据管线（M0）回填——
勾选清单随数据落地而填写，与核心系列路线图对照其卡清单的写法一致。

## M0 —— 数据管线（所有子路线图的前置）

`cards/cards.json`（1190 条，精简 schema `id/name/cost/attack/health/type/mechanics`）
里几乎没有真实的 2025–2026 卡——现存的 DREAM/TOY/GIFT/Story 前缀是伊瑟拉的
梦境卡、礼物英雄与谜题卡，不是扩展。M0 是地基：

- [x] **数据源（决策 D1）**——获取真实卡库转储。决策（2026-08-08）：**hearthstonejson
  转储**（`api.hearthstonejson.com/v1/latest/enUS/cards.collectible.json`，社区维护、
  完整卡库、SabberStone 生态同源）。已按系列切片入库：`cards/data/EMERALD_DREAM.json`
  （183，含 38 迷你）、`THE_LOST_CITY.json`（183，含 38）、`TIME_TRAVEL.json`
  （183，含 38）、`CATACLYSM.json`（164，含 29 职业套装）、`ESCAPEFROM_VIOLET_HOLD.json`
  （135）；每张卡带 id/name/cost/type/攻/血/耐久/**种族/职业**/**效果文本**（叙述）、
  关键字（mechanics）、可收集性。复现：`tools/fetch_expansion_sets.py`；转储 sha256 见
  `cards/data/SOURCE.md`。
- [x] **Schema 扩展**——`cards/cards.json` 条目补可选字段 `text`/`race`/`cardClass`/
  `classes`/`set`/`collectible`（M0.2，PR #132：764/1190 条从转储按 ID 回填，
  复现脚本 `tools/backfill_card_fields.py`）。`build.rs`/`generated.rs`：生成
  CardDef 字面量填真实 `race`（新增 `Race::Naga`；"ALL" 无单一种族映射保持 None），
  新增 `generated::card_set(id)` 注册表（`CardSet` 枚举：Classic/Core/五扩展/Other，
  未知/自定义 ID 兜底 Classic）。白板卡保持生成常量基线；有效果叙述的卡照
  `core_w*.rs` 模式手写效果文件。text/class/collectible 留在 JSON 层（接线元数据）。
- [x] **系列注册**（M0.3，PR #133）——`cards/cards.json` 并入五系列 848 张卡
  （复现脚本 `tools/merge_expansion_sets.py`）；build.rs 生成 per-set 组常量
  （`EMERALD_DREAM_CARDS` 183 / `THE_LOST_CITY_CARDS` 183 / `TIME_TRAVEL_CARDS`
  183 / `CATACLYSM_CARDS` 164 / `ESCAPEFROM_VIOLET_HOLD_CARDS` 135）与扁平
  `EXPANSION_CARDS` 切片（`card_by_id` 引擎可用）。**D3 两态**：`ALL_CARDS` 保持
  手写池（54 处调用点零改动），`pool::in_active_window`（Classic|Core，单次切换点）
  过滤全部抽样池，`is_standard`/`is_expansion` 过滤器就位。顺带发现并登记核心重印
  重平衡：Babbling Bookcase（CORE_EDR_001 2/4 vs EDR_001 3/3）。
- [x] **校验**（M0.4，PR #134）——`expansion_ids_unique`：生成注册表 ID 唯一、
  扩展 ID 与手写池无交集；`expansion_differential_gate`：每张扩展卡要么手写、
  要么与生成基线逐字段一致（`expansion_differential_rebalanced` 例外表 + M1+ 波
  的 tripwire）。`core_reprints_match_originals` 模式延续既有保真测试。

## 引擎机制缺口（扩展需要 vs. 现状）

**已有**（核心系列 W0–W8）：冲锋/吸血/重生/连击边/可交易/法术伤害管线、英雄替换
（`CardType::Hero`）、地点、附魔衍生物、抉择（简化：自动随机）、发现（简化：随机）、
奥秘、光环、无任务版的触发事件清单。

**缺失——新引擎原语（各随 F5 场景落地）：**

| 原语 | 需要方 | 说明 |
|---|---|---|
| 英雄技能强化/变换 + 每回合选择 | 灌注（EDR）、死亡之翼英雄（CAT） | `HeroPowerDef` 存在但静态；需游戏内升级计数、阈值触发、可结算的"选择效果"英雄技能 |
| 任务区 + 任务进度组件 | 安戈洛 | 引擎无任务区；需 `Zone::Quest`（或每玩家任务槽）、进度事件、奖励结算 |
| 效果重放 / 上张效果历史 | 时光倒流（TTW） | 追踪上张打出卡的效果（与更早一张），激活时重放——与死亡阶段排序 |
| 巨像附属部件 | 大灾变 | 随从登场时连带召唤附属部件，随本体死亡、毗邻占位——新召唤路径 |
| 分裂卡两半（粉碎） | 大灾变 | 抽到的卡一分为二、可重组——触及抽牌、手牌与打出结算 |
| 同族死亡计数 | 安戈洛 | "Kindred: X"——按卡文本的触发集做逐卡计数 |
| ~~灼烧再亡语~~ | ~~EDR 迷你~~ | 已移除（M0.5 数据核实：转储无此关键字） |
| 规则覆写（破规者） | 紫罗兰监狱 | 逐卡的规则例外（重复传说、额外抽牌…）——逐一对照规则引擎硬编码不变量 |
| 真实抉择结算 | EDR（全职业） | 清偿已登记简化：选择面进入 `legal_actions`/Python 绑定 |

## 决策点（已决——2026-08-08 全部定案，随 M0 记录）

- **D1 —— 卡数据源** ✅ **hearthstonejson 转储**（`api.hearthstonejson.com`
  collectible 转储；M0.1 落地，数据在 `cards/data/`，sha256 见 `SOURCE.md`）。

  落地时带 `(simplified …)` 标记与 `fidelity-debt.md` 行，与核心波一致——除非该波
  完整实现。
- **D3 —— RL 池策略** ✅ **真实标准池**：训练池切 2025–2026 + 核心。引擎经池
  过滤器同时支持两态；训练切换在收尾单次执行（同 2026-08-08 的 D4 决策流程），
  观测编码扩展（任务进度、灌注等级；地点充能已有）与 `_load_debt_ids()` 对新波
  文件的 glob 扩展一并处理。
- **D4 —— 波形态** ✅ **按扩展分波**（机制随系列走、数据按系列落地）。
- **D5 —— 中文命名** ✅ M0 期间按官方本地化回填系列/职业名；卡名沿用
  `classic-cards-zh.md` 惯例（英文）。
